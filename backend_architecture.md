# Backend & Database Architecture (Firebase)

Yeh document aapke Todo App (Google Calendar Style) ke Backend aur Database architecture ko detail mein explain karta hai. Hum Firebase services ka use karenge taaki aapko khud ka server na likhna pade.

## 1. Firebase Services Used
- **Authentication:** Google Sign-In (Firebase Auth).
- **Database:** Cloud Firestore (Real-time NoSQL DB).

## 2. Firestore Database Schema

Firestore NoSQL hai, isme hum relations ki jagah **Collections** aur **Documents** use karte hain. Har user ka data secure rakhne ke liye hum ye hierarchy follow karenge:

**Path:** `users/{uid}/tasks/{taskId}`

### A. Users Collection (`users`)
Jab koi user pehli baar Google se login karta hai, toh hum uski details yahan save karenge taaki app ke paas uska record ho.
- **Document ID:** `uid` (Google Auth se milne wali unique ID)
- **Fields:**
  - `email` (String) - e.g., "user@gmail.com"
  - `displayName` (String) - e.g., "Rahul Sharma"
  - `photoUrl` (String) - Profile picture link
  - `createdAt` (Timestamp) - Account banne ka time

### B. Tasks Sub-Collection (`users/{uid}/tasks`)
Har user ke apne tasks is sub-collection ke andar documents ki tarah save honge.
- **Document ID:** Auto-generated by Firestore
- **Fields:**
  - `title` (String) - Task ka naam
  - `startTime` (Timestamp)
  - `endTime` (Timestamp)
  - `status` (String) - `"active"` ya `"done"`.
  - `createdAt` (Timestamp) - Sorting ke liye (e.g., newest tasks first)

## 3. The "Late" Task Logic (Important)

Ek task "Late" kab hota hai? Jab uska `endTime` current waqt se piche chhut jaye, lekin uska status abhi bhi `"active"` ho.

**Kaise Handle Hoga? (Frontend Approach)**
Server (Cloud Functions) par lagatar time check karne ke bajaye (jo ki Firebase mein paid hota hai), hum **Frontend Logic** use karenge:
1. Database mein task hamesha `"active"` state mein hi rahega.
2. Jab app data read karegi, toh Frontend check karega: `if (current_time > task.endTime && task.status == 'active')`.
3. Agar yeh condition true hoti hai, toh app us task ko automatically **Red (Late)** color mein dikhayegi.
4. Agar user us late task pe "To Do" button dabata hai, toh uska `endTime` aage (future) shift kar diya jayega.
Is approach se aapki Firebase cost $0 rahegi aur app bilkul perfect kaam karegi!

## 4. Backend Services Directory Structure (Flutter)

Flutter code mein backend se baat karne wale functions in files mein honge:

```text
lib/
 ┗ services/
   ┣ auth_service.dart     # Google login/logout aur users collection mein data save karne ka code.
   ┗ db_service.dart       # Tasks CRUD (Create, Read, Update, Delete) karne ka code.
```
